# Дамп flash MB90F395HA через UART (Boot ROM Fujitsu)

> [!WARNING]
> **`fujitsu_flasher.py` в этой папке не проверен и для работы не годится.**
> Коды его команд (`0x05`, `0x10`, `0x40` …) не взяты ни из одного
> документа Fujitsu и ни разу не получили ответа от чипа (проверка
> 2026-10-24). Скрипт запускается только с флагом `--unverified-protocol`.
> Для дампа используйте **isp-mb9x** — ниже.

## Чем читать

**isp-mb9x 3.00** (Windows, командная строка) — работает поверх файлов
официального «FUJITSU FLASH MCU Programmer for F2MC-16LX»: ему нужен
`CHIPDEF.ini` из установленной программы Fujitsu (путь задаётся в
`isp-mb9x.cfg`, у программы Fujitsu он в `C:\Program Files (x86)\…`).

Команда **только чтения** (ключ `/R` — read; без него программа стирает и
пишет чип, поэтому `/R` обязателен):

```
.\isp-mb9x.exe /LCOM4 /t /a /o5 /MB90F395H /b kombi_dump.bin /R /sf80000
```

| Ключ | Смысл |
|---|---|
| `/LCOM4` | COM-порт переходника (подставьте свой номер) |
| `/t` | не дёргать RTS/DTR — сброс делаем вручную |
| `/a` | автоподбор скорости |
| `/o5` | частота кварца 5 МГц |
| `/MB90F395H` | тип микроконтроллера |
| `/b kombi_dump.bin` | файл, куда сохранить дамп (обязателен и для чтения) |
| `/R` | **только чтение** |
| `/sf80000` | начальный адрес flash |

Эти ключи — из реального запуска программы владельцем проекта; синхронизации
с чипом тогда ещё не было (распайка была по старой схеме).

## Подключение

Актуальные схемы обоих вариантов — на странице
[rzhavoezubilo.github.io/Dash-BMW-e90/uart/](https://rzhavoezubilo.github.io/Dash-BMW-e90/uart/)
и в [FUJITSU_MB90F395_UART_PINOUT.md](../../docs/hardware/FUJITSU_MB90F395_UART_PINOUT.md) §3.
Начинать с **варианта A** — с ним сторонний участник реально снял дамп:

```
TXD переходника -> SIN0, pin 7
RXD переходника <- SOT0, pin 5
GND переходника -> VSS,  pin 16
MD2 (87), MD1 (88) -> +5 В (подтяжка на плате, проверить мультиметром)
MD0 (89)            -> GND
P00 (93), P01 (94)  -> GND через ~10 кОм
переходник в режиме 5 В, его VCC не подключать
```

Плата питается отдельно, +12 В на разъём X11175 (pin 9 = +12 В, pin 18 = GND).

## Порядок

1. Запаять по варианту A, проверить мультиметром +5 В на MD2/MD1 и
   отсутствие перемычек между соседними выводами.
2. Подать питание, запустить команду выше, затем коротко замкнуть
   RST (pin 90) на GND.
3. **Прочитать дважды** в разные файлы и сравнить — дамп годится, только
   если файлы совпадают байт в байт:
   В PowerShell (должно ответить «различия не найдены»):
   ```
   fc.exe /b kombi_dump_1.bin kombi_dump_2.bin
   ```
4. Сохранить дамп в `local-firmware/` (он не попадает в репозиторий) —
   это резервная копия и исходник для патча.
5. Если синхронизации нет — попробовать вариант B целиком, не по одному проводу.
