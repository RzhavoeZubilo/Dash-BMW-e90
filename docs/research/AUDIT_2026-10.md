# Аудит достоверности проекта (2026-10-24)

Систематическая проверка всех документов, инструментов и страниц сайта на
предмет **конкретных технических утверждений**, выдаваемых за факт (адреса,
опкоды, байтовые последовательности, команды протокола, номера выводов,
значения регистров, пометки «подтверждено»/«проверено»). Повод: часть
материалов, оставленных ранней сессией, содержала выдумки, поданные как факт
(уже исправлены: опкоды в `kombi_patcher.py` — коммит `7f9914b`; коды команд
Boot ROM в `fujitsu_flasher.py` — коммит `c40ac51`).

## Как проверялось (первичные источники)

| Источник | Что подтверждает | Как использован |
|---|---|---|
| 14 образов `local-firmware/*.0pa`/`*.0ba` | адреса, байты, таблицы, карта памяти, векторная таблица | `tools/re/dump_flat.py` → плоский бинарь; `tools/re/f2mc_disasm.py` `disassemble()`; `tools/re/parse_ihex.py` |
| `F2MC.slaspec` (Ghidra-модуль F2MC-16LX) | подписи опкодов | сверка мнемоник (`0x63 JMPP`, `0x65 CALLP`, …) |
| `local-firmware/KOMB87_spdaten69.prg` (SGBD) | джобы, таблицы статусов/сегментов/аутентификации | `~/…/BimmerDaten/decoderPrg.py` `parse_prg` |
| `DBC-mega-merge/bmw_e9x_e8x1_merged.dbc` | CAN ID и сигналы | прямое сопоставление `BO_`/`SG_` |
| `.DAT`/`.HIS`/`.HWH` (SP-Daten E89) | ZB-NR → HW-NR, семейства HKOML2/DKOML2 | прямой разбор |
| Fujitsu PDF (`инструкции фуджицу/`) | режим внутрисхемного программирования MCU | `pdftotext`, раздел «4. PINS USED FOR ON-BOARD REPROGRAMMING» |
| `080100HKOML2.ipo` / `080101DKOML2.ipo` | порядок джобов прошивки, строки аутентификации | `strings`, побайтовый diff |

Легенда вердиктов: **✅ подтверждено** (есть первичный источник) ·
**⚠️ не подтверждено** (источника в репозитории нет, не выдумка, но и не факт) ·
**❌ опровергнуто** (первичные данные противоречат) · **🔧 исправлено** /
**📝 помечено** (что сделано).

## docs/BMW_KOMBI_PL2_RESEARCH.md

Главный «справочник». Тон — «факт», но содержимое — пересказ рабочих журналов
(`HANDOFF.md`/`ANALYSIS_NOTES.md`), где те же утверждения помечены как гипотезы
или прямо опровергнуты. Проверено по образам и журналам:

| Утверждение | Вердикт | Основание / действие |
|---|---|---|
| MCU MB90F395HA, Flash 512 КБ `0xF80000–0xFFFFFF` | ✅ | образы: покрытие ровно в этом окне; CHIPDEF.ini `FlashSize=0x80000` |
| Дискриминатор поколения `0xF80042`: `0x08` (0101) / `0x09` (0102) | ✅ | образы: `0x08` у ранних, `0x09` у 9260849/9280355/9283869/9316169 |
| §3 Рамка передачи `01 02 01 01` только у DKOML2, `00 00 00 FF` у HKOML2 | ❌ частично | у DKOML2 таблица `01 02 01 01` есть (9283870A@`0xF83C60`/`0xF83DE2`), у HKOML2 её нет — **но** «`00 00 00 FF` забито во всех 9/9 HKOML2» не воспроизводится: по `0xF83DE2` у HKOML2 просто другие данные, не `00 00 00 FF`. 📝 помечено как неточность |
| §3 Рамка = тип коробки (DKG) | ❌ | опровергнуто владельцем и самим кодом (`HANDOFF.md`, правка 2026-08-04): рамка зависит только от варианта прошивки |
| §3 CAN `0x1D2`, `B1 & 0x03` → `RAM[0x0CFD]` → индекс таблицы | ✅ | дизасм `0xFAF7FF`/`0xFAF81F` (4/4 DKOML2, 0/9 HKOML2); но поле **недокументировано** в DBC (не `ShiftLeverMode`) |
| §3 `02` = мигание «период 50 тиков» | ⚠️ | таймер на `0xFE6257` есть; «50» — из кода, конкретика рендера не до конца прослежена (см. `HANDOFF.md`) |
| §9 `set_telltale` `CALLP [0xFD47ED]`, ID `0x24` (машина ACC), `0x25` (разметка) | ✅ | `0xFD47ED` — 68 вызовов; `0xFC0F38` кладёт `0x24`, `0xFC0F79` — `0x25` перед `CALLP [0xFD47ED]` |
| §9.2 Shift-light: пороги 5000/5500/6000/6200 RPM, `CALLP [0xFF2843]` «bars(level,max)» | ❌ / ⚠️ | `0xFF2843` — реальная функция (33 вызова), **но что она делает — не проверено** (`HANDOFF.md`:4056). Пороги RPM как констант в образе **нет** (5500/6200 не встречаются). 📝 помечено |
| §10 8-я передача: `0xF83DE6` = `" 1234567"`, патч `0xF83DEE` `0x20`→`0x38`, `0xFB9958` `D7`→`D8`, `RAM[0x0B2B]` цифра | ✅ (только 9283870A) | дизасм подтверждает таблицу и предел `MOVN A,#7` на `0xFB9958`; исходные байты совпадают только в 9283870A |
| §10 `RAM[0x0B2A]` = первый символ (`'D'`/`'M'`/`'S'`) | ⚠️ | в разобранном месте туда пишется только `'<'`/`'>'`/пробел (`HANDOFF.md`:4093) |
| §11 Таблица дескрипторов `0xF83912`, 36×12 байт | ✅ | дизасм: по `0xF83912` в 9283870A регулярная таблица 12-байтных записей |
| §11 «Свободный карман `0xFB9FF0–0xFBBFFF` (8208 байт)» | ✅ | образы: диапазон `0xFB9FF0–0xFBC000` = сплошь `0xFF`, не пишется ни одним файлом |
| §13 `0xFC06A0` stepper, `0xFCAC65` sweep, `0xFC1D50 render_lcd_text`, `0xFDC1CD bc_dispatcher` | ❌ | `0xFC06A0`/`0xFC1D50`/`0xFCAC65` не имеют **ни одного** `CALLP`-вызова; `0xFCAC65` дизассемблируется с середины инструкции. Имена функций — домыслы (`HANDOFF.md`:4097). 📝 помечено |
| §5.1 «C09 → D1..D8, S1..S8, M1..M8» | ⚠️ | дизасм показывает заводскую 8-ю передачу только в 9316169A (High) и 9347674A (DKG) и только для цифры передачи; `S1..S8`/`M1..M8` отдельно не подтверждены |
| §2 «Разрешение LCD (крупный/мелкий растр)», числа 0.32/0.5 мм | ⚠️ | уже помечено в самом документе как неподтверждённое; подтверждения нет |
| §6 таблицы ZB-NR → HW-NR (High/Low) | ✅ в основном | сверено с `HKOML2.DAT`/`DKOML2.DAT`: `9280339–42→9280355`, `9283824/25/43/44/46/47→9283869`, `9316139/57/72→9316169`, `4256409–40→4256458` — совпадают. **Low BKOML2** (`9283807/08/21`, `9316119/20/27`): в локальных `.DAT` этих ZB **нет** (нет файла BKOML2.DAT) — ⚠️ не подтверждено |
| §7.2 программатор VVDI Prog/Orange5/UPA-USB по `SIN0/SOT0` | ❌ | источником не подтверждено; уже помечено в `BMW_KOMBI_FLASHER_PLAN.md` §H3 как недостоверное |

**Действие:** документ оставлен как есть по содержанию (детали уже разобраны в
журналах), но в шапку добавлена ссылка на этот аудит и предупреждение, что §9.2
(пороги/семантика `0xFF2843`) и §13 (имена `0xFC06A0`/`0xFCAC65`/`0xFC1D50`/

## Итог

* **Опровергнуто и исправлено/помечено:** смещение diff `.ipo` (`0x8036`→`0x8046`);
  уровни MD в UART-доке (`MD2=H, MD1=H, MD0=L` по локальному PDF); число джобов
  (133 описанных из 140); имена функций §13 и семантика/пороги §9.2 в RESEARCH;
  модули `mods/*.asm` (непроверенный/опровергнутый код) снабжены врезкой.
* **Подтверждено образами/SGBD/DBC:** карта памяти и защищённая область, таблица
  `0xFFBF50`, дискриминаторы семейств, патч 8-й передачи (9283870A),
  `set_telltale`/ID ACC, таблицы SGBD, CAN ID в `DISPLAYABLE_PARAMETERS`.
* **Осталось «не подтверждено» (не выдумка, но и не факт):** номера ног Boot ROM
  (`SIN4/SOT4`), алгоритм `$CHECKSUMME`, Low BKOML2 ZB↔HW (нет файлов),
  семантика `0xFF2843`, `RAM[0x0B2A]`. Так и помечено — заменять нечем, пока нет
  дампа/источника.

> Правило проекта подтверждено этим аудитом: **то, чего не видно в первичных
> данных, подаётся как «не подтверждено», а не как факт.** Где истинное значение
> неизвестно — так и написано.
